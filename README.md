# muhajjar.com — Munther AlHajjar

Bilingual (Arabic RTL / English LTR) executive portfolio. React + TypeScript + Vite, prerendered to static HTML, so it runs on any static host (Hostinger shared hosting included) with no Node.js on the server.

> **بالعربية باختصار:** شغّل `npm install` ثم `npm run build`، وارفع محتويات مجلد `dist` (وليس المجلد نفسه) إلى `public_html` في Hostinger. تفاصيل النشر خطوة بخطوة في قسم «النشر على Hostinger» أدناه، وقائمة التحقق في `DEPLOY-CHECKLIST.md`.

## Requirements

- Node.js 20 or newer (22 recommended) and npm.

## Commands

| Command | What it does |
| --- | --- |
| `npm install` | Installs dependencies (first time only). |
| `npm run dev` | Local development server at http://localhost:5173 (client-rendered, hot reload). |
| `npm run build` | Type-checks, builds, and prerenders every page into `dist/`. |
| `npm run preview` | Serves `dist/` at http://localhost:4173 to check the production build. |
| `npm run images` | Rebuilds `src/data/images.json` after you add or replace project images. |

## How it is built

- **30 static pages**: home, about, experience, selected projects (index + 10 case studies), expertise — each in Arabic (`/`) and English (`/en/`), plus `404.html` and `en/404.html`.
- `scripts/prerender.mjs` renders every route with React's server renderer, writes `dist/<route>/index.html`, inlines the stylesheet, and generates `sitemap.xml` (with `hreflang` alternates) and `robots.txt`.
- The browser then hydrates each page for the interactive parts: theme toggle, mobile menu, project filter, copy-email button, count-up numbers, reveal motion, and the Riyadh clock.
- **Runtime size**: production builds swap React for Preact's React-compatible runtime (about 28 KB gzipped instead of about 90 KB). The source is plain React. To build with React itself: `USE_REACT=1 npm run build` (both builds were tested).
- No tracking, cookies, API keys, environment variables, or third-party requests. All fonts are self-hosted.

## Where things live

```
src/
  data/profile.ts     ← name, contact, bio, metrics, experience, education, certifications, award
  data/projects.ts    ← the 10 selected projects (case-study text and image references)
  data/expertise.ts   ← capability groups and the four-step process
  data/images.json    ← image sizes (generated by `npm run images`)
  i18n.ts             ← interface labels in Arabic and English
  routes.ts           ← URL structure (Arabic at /, English at /en/)
  seo.ts              ← titles, descriptions, canonical, hreflang, Open Graph, JSON-LD
  pages/, components/ ← layout and pages
  styles/global.css   ← the whole design system (colour tokens at the top)
public/
  fonts/              ← Thmanyah Sans + Thmanyah Serif Display (WOFF2)
  images/             ← portrait, project images, logos
  files/              ← CV and cover-letter PDFs (Arabic and English)
  .htaccess           ← HTTPS redirect, 404 pages, caching, compression
  og-image.jpg, favicon.svg, favicon-32.png, apple-touch-icon.png, icon-512.png
```

All career facts are in `src/data`. Edit there and rebuild; no other file holds content.

## Replacing assets

**Profile photograph** — replace `public/images/portrait-480.webp`, `portrait-900.webp` and `portrait-900.jpg` with square crops of the new photo (same names, 480 × 480 and 900 × 900). Then run `npm run images`. The site shows the portrait in warm monochrome; to show it in colour, change `--portrait-filter` in `src/styles/global.css` to `none`. A photo against a plain background will look best (the current background has a fine line pattern).

**Project images** — export WebP files (for example with squoosh.app) named `<key>-720.webp` and `<key>-1400.webp` into `public/images/projects/`, run `npm run images`, then reference `<key>` in `src/data/projects.ts` (`cover` or `gallery`). Always state where the image comes from in `imageSource`. Projects without imagery show a typographic plate instead of stock photography.

**Logos** — transparent WebP or PNG in `public/images/logos/`, listed in `organisations` in `src/data/profile.ts`. Logos are shown as single-colour silhouettes so they sit quietly in both themes.

**Favicon / social image** — replace `public/favicon.svg`, `favicon-32.png`, `apple-touch-icon.png` (180 × 180), `icon-512.png`, and `og-image.jpg` (1200 × 630).

**Fonts** — WOFF2 files in `public/fonts/`, declared at the top of `src/styles/global.css`. Thmanyah fonts are distributed by Thmanyah under their own licence (embedded in the font files); review it before commercial use. IBM Plex Mono comes from `@fontsource/ibm-plex-mono` (SIL Open Font License).

**CV PDFs** — replace the four files in `public/files/` keeping the same names.

## Deploying to Hostinger

Two options. Both publish the **contents** of `dist/` to the site root (`public_html`).

### Option A — upload the build (simplest)

1. `npm install && npm run build`.
2. In hPanel open **Websites → muhajjar.com → File Manager → public_html**.
3. Download a backup of the current `public_html` (select all → Compress → download the archive).
4. Delete the old site files from `public_html` (keep the backup).
5. Upload everything inside `dist/`, including the hidden `.htaccess` file (in File Manager enable *Show hidden files*; with FTP make sure dotfiles are transferred). Uploading a zip of `dist/`'s contents and choosing *Extract* is fastest.
6. Open https://muhajjar.com/ and https://muhajjar.com/en/ and run the checks in `DEPLOY-CHECKLIST.md`.

### Option B — Git auto-deploy (how muhajjar.com is set up)

The repository `mualhajjar/muhajjar-website` has two branches:

- **`source`** — this project (the code you edit).
- **`main`** — the finished static site only. Hostinger's Git deployment pulls `main` into `public_html` automatically, as before.

Publishing flow: edit on `source` and push. The workflow `.github/workflows/deploy.yml` runs on GitHub, builds the site, and commits the new `dist/` to `main`; Hostinger then deploys it. Do not edit `main` by hand; the next build overwrites it.

The previous single-page site is kept on the branch `legacy-site`.

If the workflow ever cannot run (for example, Actions disabled), build locally and copy `dist/` onto `main` yourself, or use Option A.

### Domain and HTTPS

- **Domain**: if muhajjar.com is registered at Hostinger it is already pointed. If it is registered elsewhere, set the domain's nameservers to Hostinger's (shown under hPanel → Domains → DNS / Nameservers), or point the `A` record for `@` and `www` to the IP shown in hPanel. DNS changes can take up to 24 hours.
- **HTTPS**: hPanel → **Security → SSL** → install the free SSL certificate for muhajjar.com (and www). Wait until it shows *Active*.
- The `.htaccess` already redirects `http://` and `www.` to `https://muhajjar.com`. If you ever see a redirect loop, remove the `www` condition and enable *Force HTTPS* in hPanel instead.

### After going live

- Google Search Console: add the property `https://muhajjar.com/`, then submit `https://muhajjar.com/sitemap.xml`.
- Check the social preview with LinkedIn's Post Inspector (https://www.linkedin.com/post-inspector/) — LinkedIn caches previews.

## Contact form

There is no form on purpose: the contact section links straight to email, WhatsApp, LinkedIn, and the résumé, so there is no backend to maintain. If you want a form later, a static-friendly service such as Formspree, Web3Forms, or Hostinger's own form handler can be added without a server; each needs an account and a form endpoint, and the endpoint must not be a secret key.
